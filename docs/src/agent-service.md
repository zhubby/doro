# Service Installation

Doro can install the control plane and Agent as managed host services. Linux uses systemd. macOS uses launchd through `launchctl`; Launchpad is only the macOS GUI app launcher and is not the service manager.

The Makefile exposes platform-neutral targets that choose the manager from `uname`:

```bash
make control-plane-service-install
make agent-service-install
```

On Linux these dispatch to `*-systemd-*`. On macOS they dispatch to `*-launchd-*`. You can force the manager explicitly:

```bash
make control-plane-service-install DORO_SERVICE_MANAGER=systemd
make control-plane-service-install DORO_SERVICE_MANAGER=launchd
```

## Control Plane

Install the control plane service:

```bash
make control-plane-service-install
```

Before first start, review `/etc/doro/control-plane.toml` for the database URL, bind addresses, TLS posture, and security settings:

```toml
[server]
console_bind = "0.0.0.0:8787"
agent_bind = "0.0.0.0:8788"

[store]
backend = "postgres"
database_url = "postgres://doro:doro@127.0.0.1:5432/doro"
```

Then start and inspect the service:

```bash
make control-plane-service-start
make control-plane-service-status
```

Useful commands:

```bash
make control-plane-service-logs
make control-plane-service-restart
make control-plane-service-stop
make control-plane-service-uninstall
```

`control-plane-service-uninstall` removes the service definition and disables/unloads the service. It leaves `/etc/doro/control-plane.toml`, the state directory, the installed `doro` binary, and service user data in place.

## Agent

Install the Agent service:

```bash
make agent-service-install
```

Before first start, add the enrollment token generated by the control plane to `/etc/doro/agent.toml`:

```toml
[agent]
control_plane_url = "http://127.0.0.1:8788"
hostname = "doro-host"
enrollment_token = "redacted"
```

Then start and inspect the service:

```bash
make agent-service-start
make agent-service-status
```

Useful commands:

```bash
make agent-service-logs
make agent-service-restart
make agent-service-stop
make agent-service-uninstall
```

`agent-service-uninstall` removes the service definition and disables/unloads the service. It leaves `/etc/doro/agent.toml`, local state, the installed `doro` binary, and enrolled identity data in place.

## Linux systemd

Explicit Linux targets:

```bash
make control-plane-systemd-install
make control-plane-systemd-start
make control-plane-systemd-status
make control-plane-systemd-logs

make agent-systemd-install
make agent-systemd-start
make agent-systemd-status
make agent-systemd-logs
```

The rendered units run:

```bash
/usr/local/bin/doro --config /etc/doro/control-plane.toml control-plane
/usr/local/bin/doro --config /etc/doro/agent.toml agent
```

Systemd defaults:

```text
DORO_CONTROL_PLANE_SERVICE=doro-control-plane
DORO_AGENT_SERVICE=doro-agent
DORO_CONTROL_PLANE_STATE_DIR=/var/lib/doro
DORO_AGENT_STATE_DIR=/var/lib/doro
DORO_CONTROL_PLANE_USER=doro
DORO_AGENT_USER=doro
```

Use `DORO_AGENT_SUPPLEMENTARY_GROUPS=docker` when the Linux Agent needs access to `/var/run/docker.sock` on distributions where Docker socket access is granted through the `docker` group.

## macOS launchd

Explicit macOS targets:

```bash
make control-plane-launchd-install
make control-plane-launchd-start
make control-plane-launchd-status
make control-plane-launchd-logs

make agent-launchd-install
make agent-launchd-start
make agent-launchd-status
make agent-launchd-logs
```

The launchd plists are installed as LaunchDaemons by default:

```text
/Library/LaunchDaemons/com.doro.control-plane.plist
/Library/LaunchDaemons/com.doro.agent.plist
```

macOS defaults:

```text
DORO_LAUNCHD_DOMAIN=system
DORO_LAUNCHD_DIR=/Library/LaunchDaemons
DORO_CONTROL_PLANE_LAUNCHD_LABEL=com.doro.control-plane
DORO_AGENT_LAUNCHD_LABEL=com.doro.agent
DORO_CONTROL_PLANE_STATE_DIR=/Library/Application Support/Doro
DORO_AGENT_STATE_DIR=/Library/Application Support/Doro
DORO_CONTROL_PLANE_USER=<current user>
DORO_AGENT_USER=<current user>
```

The rendered plists run:

```bash
/usr/local/bin/doro --config /etc/doro/control-plane.toml control-plane
/usr/local/bin/doro --config /etc/doro/agent.toml agent
```

Logs are written under the configured service log directory, defaulting to:

```text
/Library/Application Support/Doro/logs/control-plane.out.log
/Library/Application Support/Doro/logs/control-plane.err.log
/Library/Application Support/Doro/logs/agent.out.log
/Library/Application Support/Doro/logs/agent.err.log
```

## Variables

Common override examples:

```bash
make control-plane-service-install \
  DORO_CONTROL_PLANE_DATABASE_URL=postgres://doro:doro@postgres.lan:5432/doro

make agent-service-install \
  DORO_AGENT_CONTROL_PLANE_URL=http://control-plane.lan:8788 \
  DORO_AGENT_HOSTNAME=nas-1
```

Shared variables:

```text
DORO_INSTALL_PREFIX=/usr/local
DORO_INSTALLED_BIN=/usr/local/bin/doro
DORO_CONTROL_PLANE_CONFIG=/etc/doro/control-plane.toml
DORO_AGENT_CONFIG=/etc/doro/agent.toml
DORO_CONTROL_PLANE_CONSOLE_BIND=0.0.0.0:8787
DORO_CONTROL_PLANE_AGENT_BIND=0.0.0.0:8788
DORO_CONTROL_PLANE_DATABASE_URL=postgres://doro:doro@127.0.0.1:5432/doro
DORO_AGENT_CONTROL_PLANE_URL=http://127.0.0.1:8788
```
